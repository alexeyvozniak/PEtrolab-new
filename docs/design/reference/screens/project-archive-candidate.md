# Перенос проекта

Статус — кандидат экрана. Сценарий AT-34 и раздел 20.3 основной спецификации.

При сохранении пользователь выбирает состав архива. «Проект» содержит базу и историю. «Проект и источники» добавляет исходные аналитические файлы. «Полный проект» добавляет изображения. Перед сохранением показаны имя проекта, состав, недоступные исходники и путь назначения. После сохранения видны путь и состав архива.

При открытии архива PetroLab показывает проект, версию схемы, включённые файлы и итог проверки. Восстановление предлагает новый каталог. Для замены закрытого проекта экран показывает путь назначения и поясняет, что весь прежний каталог сохранится рядом. После подтверждённой замены показываются путь восстановленного проекта и путь резервной копии. Повреждённый архив оставляет каталог без изменений.

Для приёмки используются три уровня архива. Проверяются состав, SHA-256, записи анализов, исходные рецепты и связи изображений. Отдельный сценарий сверяет отказ при повреждении, отсутствие изменений при отказе и побайтовую копию прежнего каталога после подтверждённой замены.

Предварительная проверка использует `project.archive.inspect` с `archive_path`. Ответ содержит проверенный `manifest` и `unpacked_size` в байтах. Сервис сверяет все файлы и открывает временную копию SQLite для проверки схемы. При восстановлении проверки выполняются повторно для файла, выбранного к восстановлению.

До упаковки `project.archive.check_export` принимает `project_database_path` и `level`. Ответ содержит ID проекта, выбранный уровень, `ready`, известный объём после распаковки и отдельные статусы файлов. `unavailable` означает, что файл не удалось прочитать или включить, `changed` означает несовпадение SHA-256. Для создания архива сервис сверяет файлы заново.
