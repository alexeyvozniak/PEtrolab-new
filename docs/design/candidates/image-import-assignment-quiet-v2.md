# Импорт изображений / назначение — quiet v2

- **Статус:** кандидат; не является эталоном и не разрешает изменение production UI.
- **Дата:** 2026-09-22.
- **Основание:** утверждённый сценарий `image-import-sample-assignment-v1`, аудит
  `docs/qa/IMAGE_POINTS_UX_AUDIT_2026-09-22.md`, предпочтение пользователя от
  2026-09-22: один текущий вопрос, одно главное действие, свёрнутые второстепенные
  настройки и отсутствие повторяющихся статусов.
- **Сохраняемые сценарии:** AT-22, AT-23, явное подтверждение каждого назначения,
  массовое назначение отмеченных строк, блокировка дубликатов, неизменность
  исходных файлов.

## Решение, которое требуется утвердить

Первый шаг мастера остаётся экраном назначения Sample и шлифа, но использует **один
список файлов** вместо дублирующих друг друга левого списка и центральной таблицы.
Клик по строке открывает её инспектор справа; не создаёт назначения и не меняет
отмеченные строки.

```
Изображения в пакете  3             [Добавить изображения] [Папка]
3 в пакете   0 готовы   3 требуют проверки   0 дубликатов
──────────────────────────────────────────────────────────────────────────
☐  Файл                 Sample        Шлиф        Тип      Состояние
☑  KIV-2_A_BSE_01.tif   KIV-2         KIV-2-A      BSE      Проверить
☑  KIV-2_A_PPL_01.tif   KIV-2         KIV-2-A      PPL      Проверить
☑  KIV-2_A_XPL_01.tif   KIV-2         KIV-2-A      XPL      Проверить
                                                ┌────────────────────────┐
                                                │ KIV-2_A_BSE_01.tif      │
                                                │ Предложено из имени     │
                                                │ Sample  [KIV-2       ]  │
                                                │ Шлиф    [KIV-2-A     ]  │
                                                │ Тип     [BSE         ]  │
                                                │ Хранение [Копия ...  ]  │
                                                └────────────────────────┘
──────────────────────────────────────────────────────────────────────────
[Отмена]     0 готовы · 3 требуют проверки       [Продолжить: точки →]
```

## Иерархия и поведение

1. В верхней строке видны название этапа, счётчик пакета и только действия
   добавления. Состояние «исходные файлы не изменяются» не повторяется здесь и в
   низу: оно остаётся один раз рядом с действием импорта/отмены.
2. Четыре счётчика располагаются в одной компактной строке. Они не являются
   декоративной сводкой: «требуют проверки» и «дубликаты» фильтруют один список;
   остальные остаются информативными. При отсутствии дубликатов предупреждение не
   занимает место.
3. Единственный список содержит имя, Sample, шлиф, тип и понятное состояние:
   «готово», «проверить» или «дубликат». Полный исходный путь доступен по
   фокусу/tooltip и в инспекторе, поэтому одинаковые имена различимы.
4. При выборе одной строки инспектор показывает её поля и предложение из имени
   файла. Это один текущий вопрос: подтвердить/исправить именно это назначение.
5. Панель массовых действий появляется только после выбора **двух и более**
   строк. В ней остаются «Подтвердить предложения» и «Применить поля к выбранным»;
   отдельные поля раскрываются по этой команде. При одной или нуле отмеченных
   строк панель и массовая кнопка в инспекторе отсутствуют.
6. Нижняя панель всегда доступна с клавиатуры и содержит одно главное действие:
   «Продолжить: точки». Пока есть непроверенные строки, кнопка disabled и рядом
   видна конкретная причина («3 назначения требуют подтверждения»), а не общий
   совет. «Отмена» остаётся вторичным действием.

## Термины и ограничения

- В одном экране используются только «изображение», «Sample», «шлиф», «тип» и
  «назначение»; не чередовать «файл» и «изображение» для одного объекта без
  контекста исходного пути.
- Предложение имени файла остаётся предложением до явного подтверждения.
- Массовая операция действует только на отмеченные строки; разные BSE/PPL/XPL
  сохраняют свой тип, пока пользователь явно не меняет его.
- Пространственные точки создаются только на следующем шаге. Фокус строки не
  меняет Selection и не записывает данные.
- Дубликаты продолжают блокировать план, а исключение убирает только строку из
  временного пакета, никогда не исходный файл.

## Проверяемая приёмка после утверждения

1. Для трёх файлов BSE/PPL/XPL виден ровно один список, а массовая панель
   появляется только после отметки двух строк.
2. Подтверждение предложений меняет только отмеченные строки; типы BSE/PPL/XPL
   остаются разными.
3. У одной активной строки доступна её форма, но не действие массового применения.
4. Счётчик «требуют проверки» фильтрует список, а disabled-переход объясняет,
   сколько назначений осталось подтвердить.
5. Дубликат виден в счётчике и в единственном списке; исключение не изменяет
   исходный файл и его можно вернуть в пакет.
6. Тесты AT-22 и AT-23, сборка и новая визуальная проверка проходят без изменения
   утверждённых научных и provenance-ограничений.

## Граница следующего действия

после этого допустима реализация среза 2.
