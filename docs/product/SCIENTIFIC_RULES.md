# Scientific Rules

## Сохранность и provenance

1. Исходные файлы и импортированные значения неизменяемы после фиксации импорта. Исправление создаёт новую версию, новое преобразование или явную запись коррекции.
2. Для каждой Analysis сохраняются источник, файл, лист, исходная строка, дата импорта, метод, аналитическая сессия, единицы и пространственная привязка, если она известна.
3. Экспорт графика, таблицы или расчёта содержит ссылку на входной Work Group/список Analysis, фильтры, настройки и версии вычислительных правил.

## Измерения и преобразования

1. `Measured`, `Derived` и `Interpretation` хранятся и показываются раздельно.
2. Преобразование единиц, нормирование, пересчёт Fe и расчёт OH не перезаписывают исходное значение.
3. Для Fe всегда фиксируются исходная форма (`FeO`, `Fe2O3`, `FeOt`, `Fe_total` или иное), способ пересчёта и допущение.
4. Значения ниже предела обнаружения хранят исходную запись (`<DL`), число предела и применённое правило обработки. Их нельзя молча превращать в ноль.
5. `F не измерен`, пустая ячейка, значение `0` и `<DL` - четыре разные ситуации.
6. Если рассчитывается OH, сохраняются `OH_est_basis`, формула, допущения и входные компоненты.

## Качество и актуальность

1. Статусы строк различимы: `fresh_rows`, `stale_rows`, `valid_rows`, `invalid_rows`.
2. Предварительный просмотр не заменяет итоговую проверку. Перед сохранением импорта показывается сводка всего набора.
3. Дубликаты не удаляются автоматически. Пользователь видит правило совпадения и принимает решение: оставить, связать, пропустить или импортировать как новую версию.
4. Редактирование исходных таблиц допускается только через проверяемую процедуру с SHA-256, проверкой прежнего значения и резервной копией.
5. Derived Value и Calculation Run хранят fingerprint значимых входов, ID и версию метода. Изменение входов или метода делает прежний результат `stale`, а не обновляет его молча.
6. Независимый benchmark не может использовать production-функцию для подготовки ожидаемого результата. Для формул минералов нужны отдельные стехиометрические эталоны.

## Статистика и композиционные данные

1. CLR/ILR применяются только к одному подтверждённому домену за один Calculation Run: oxides в mass %, trace-element concentrations в одной единице либо APFU.
2. Нельзя смешивать внутри log-ratio transform оксиды, trace elements, APFU, Mg#, Cr#, score и колонки с неизвестной единицей.
3. PetroLab не подставляет произвольный pseudocount. Строки с нулём, отрицательным, пропущенным или censored значением исключаются либо обрабатываются отдельным версионированным правилом; число и ID строк фиксируются.
4. Pearson, Spearman, Kendall, StandardScaler и RobustScaler остаются доступными только с явным названием Euclidean/exploratory path и после проверки единиц.
5. PCA и clustering сохраняют список признаков, порядок, масштабирование, алгоритм, параметры, seed, версию библиотеки, исключённые Analysis ID и метрики качества.
6. Кластер не является Generation, Mineral, Rock Type или QC-решением. Его сохранение создаёт снимок Work Group с provenance исходного Calculation Run.

## Формулы, классификация и научные рекомендации

1. Formula Method хранит oxygen/cation basis, входные компоненты, Fe/valence assumptions, OH basis, end-member rules, citation и версию.
2. Неизвестный Fe3+, F, Cl или H2O не подменяется измеренным значением для получения более полного названия или формулы.
3. Mineral Recognition является suggestion-layer с версией ruleset, кандидатами и confidence. Неоднозначный результат остаётся unresolved до решения пользователя.
4. Классификационные поля из литературы хранят Source и версию геометрии. Ручной контур не выдаётся за литературное или data-derived поле.
5. Deterministic Smart Start может рекомендовать график по минералу, доступным колонкам и единицам, но не меняет научные данные и показывает основание рекомендации.

## Правки, журнал и перенос

1. Edit Draft не является сохранённым Measurement. Он может пережить перезапуск, но перед записью повторно проверяет конфликт источника.
2. Operation Journal хранит точный набор сущностей, действие, автора, время, параметры и inverse action для поддерживаемых обратимых операций.
3. Table View, Workspace Snapshot и Analysis Template не копируют Measurement и не подменяют Selection/Work Group.
4. Portable archive проверяет manifest, защищается от path traversal, выполняет SQLite integrity check и создаёт backup до подтверждённой замены workspace.
5. Optimized media в переносимом архиве является производной копией и никогда не заменяет scientific original.

## Научная честность интерфейса

1. PetroLab помогает классифицировать и визуализировать, но не выдаёт интерпретацию как установленный факт без обозначения правила и допущений.
2. Предупреждение остаётся предупреждением: оно не блокирует исследование без риска порчи данных.
3. Сравнение методов WDS/EDS, LA-ICP-MS и TIMS сохраняет метод, сессию, единицы и характер пространственного измерения.
4. График обязан позволять восстановить состав точек, оси, нормирование, применённые фильтры и исключения.

## Необратимые действия

Удаление, замена, миграция и массовая перезапись всегда показывают число и тип затрагиваемых сущностей, создают обратимый путь или резервную копию и не имеют скрытого режима выполнения.
