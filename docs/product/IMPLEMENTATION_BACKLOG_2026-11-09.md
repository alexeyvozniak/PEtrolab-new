# Рабочая последовательность доработок Desktop v2

Статус: план работ по аудиту репозитория; не заменяет утверждённые продуктовые и научные контракты.

1. **Достоверность проверок.** Привязать запуск Python-тестов в VS Code к `src` текущего репозитория, актуализировать README и проверить результат на машине с другой установленной копией пакета.
2. **Связь с физическим Sample.** Сначала подготовить и согласовать контракт выбора существующего Sample, разрешения конфликтов идентичности, отмены и provenance. Затем реализовать один источник сквозным срезом с приёмочным сценарием, не создавая связь только по совпадению имён. Для нового взаимодействия требуется утверждённый визуальный эталон.
3. **Надёжность очереди импорта.** Отдельно определить атомарное сохранение нескольких источников и восстановление черновиков после перезапуска; согласовать ADR до реализации. Проверить отсутствие частичной записи и изменений исходников при ошибке.
4. **Анализы и выборка.** Сопоставить фактические действия с AT-03–AT-09 и AT-18; закрывать обнаруженные расхождения малыми срезами с проверкой сохранения данных и истории.
5. **Графики, статистика, публикация и восстановление.** Последовательно реализовать срезы C–G из `DESKTOP_V2_IMPLEMENTATION_SEQUENCE.md`, проходя их научные, миграционные и визуальные gates. Не считать утверждённый макет свидетельством реализации.
6. **Выпуск.** Пересобрать sidecar, проверить установщик на чистой Windows, клавиатуру, доступность, DPI и визуальное соответствие; собрать доказательства приёмки.

Полный экран пород и whole-rock workflow остаются за рамками текущей версии. Очерёдность может уточняться после проверки каждого среза; открытые ограничения импорта перечислены в `../qa/SEMANTIC_IMPORT_VERIFICATION_2026-09-06.md`.
