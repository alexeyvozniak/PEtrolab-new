# Массовая обработка минералов — предложение, 2026-10-13

Статус: **первый групповой срез утверждён пользователем 2026-10-13**
(«Давай так и сделаем» в ответ на предложенный сценарий до 100 анализов).
Основание:
master §§7/11/20.2, US-28/29/30, ADR-0003 и ADR-0019.
Существующий экран минералов и одноточечная формульная панель сохраняются.
Product Design get-context: работа в текущей зелёной desktop-компоновке,
цель — обработать много анализов без повторения одинаковых действий.
Сохраняется существующая зелёная трёхпанельная компоновка; групповой режим
занимает тот же инспектор, без нового экрана и визуальной перестройки.
Наблюдаемая приёмка — AT-49 и нативные скриншоты, не только unit tests.

## Один понятный путь

1. В таблице отметить нужные анализы. Фокус открывает один анализ, но не
   добавляет его к отбору. Поиск/очередь/Filter сами не выбирают строки.
   Отдельные команды «Выбрать загруженные» и позднее «Выбрать весь результат»
   не должны называться одинаково. До действия известны точные ID и количество.
2. Компактная панель: **«Выбрано 100 · Рассчитать формулы»**. Не выводить
   научный справочник, все режимы железа и все ошибки одновременно.
3. Для первого среза — один установленный метод и один явный набор параметров
   на пакет до 100 анализов. Method/default/совместимость выдаёт Python.
   Настройки закрыты; основные допущения доступны рядом с действием.
   Разные минералы не получают первый попавшийся метод автоматически.
4. После расчёта: **«Готово 98 · Требуют решения 2»**. Ошибки остаются строками
   с ID; одна текущая проблема и действие «Следующая». Не превращать пропуск,
   `<DL>`, неизвестный Fe или анион в ноль для завершения очереди.
5. **«Сохранить 100 результатов»** доступно только для целиком пригодного
   пакета. Сохранение атомарное, повтор не создаёт дубликат. Если пользователь
   исключает проблемные строки, это новый явный scope с повторным preview;
   кнопка показывает уже новое количество. Нет молчаливого «сохранить 98».
6. Смена отбора/метода/Fe/OH убирает несохранённый preview. Ошибка оставляет
   параметры и историю. Изменение входов между preview/save отвергается Python.
   Групповой run открывается из истории любого входящего анализа; исходный
   состав не переписывается и принятие минерала не считается QC-проверкой.

## Границы первого среза и следующий масштаб

До 100 строк — реальный текущий сервисный предел, не заявление о поддержке
2000 строк в formula UI. Больший отбор не режется на скрытые пакеты.
Смешанный набор сначала явно разделяется по установленным методам; неизвестные
и неподдержанные минералы остаются видимыми. Принятие одинакового предложения
для нескольких строк — отдельное подтверждённое действие с точными ID,
повторной проверкой fingerprints и причиной; его API пока не реализован.

Следующая стадия: 1000–2000 строк, серверный обзор всего scope независимо от
пагинации, отмена/прогресс/возобновление и заранее выбранная семантика
сохранения. Не добавлять очередь заданий, новые слои или менять предел без ADR,
измеренного профиля и согласования атомарности между методами.

## Проверки UI — AT-49 (готовность подтверждается QA отдельно)

- 100 явно выбранных строк на нескольких страницах; сравнить scope и
  Analysis/Measurement ID preview, saved run и повторно открытой истории.
- Скрытие строк фильтром/фокус на другой строке не меняет Selection; очереди
  показывают загруженную часть и общий размер без ложного «всё проверено».
- Пакет с двумя ошибками: последовательное объяснение, сохранение отключено;
  исключение требует явного нового scope и повторного preview.
- Разные минералы и Fe-формы: ни автоматического общего режима, ни пропуска.
- Смена параметров/отбора, запоздавший ответ, ошибка транспорта и повтор:
  stale preview не сохраняется, параметры/старые runs не теряются.
- Реальный Tauri при 1363×936: короткая панель, нет горизонтальной прокрутки,
  Tab/Space выбора и Enter расчёта/сохранения; PNG основных состояний
  сопоставлены с утверждённым групповым эталоном.
- 101 выбранный ID: честное ограничение до запуска, не скрытый truncation.
