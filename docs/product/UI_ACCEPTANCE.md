# UI Acceptance

## Правило приёмки

Пользователь принимает поведение приложения, а не реализацию. Каждый тест ниже выполняется на реальных данных или на фиксированном тестовом проекте и оставляет: автоматический результат, видео/лог при ошибке и скриншоты ключевых состояний.

## Условия провала

Тест считается проваленным, если приложение: теряет связь между точкой и источником; меняет исходные данные молча; показывает Selection как будто это сохранённая группа; меняет Selection при простом фокусе на Point; удаляет Source вместо обратимого исключения; использует скрытие на графике как QC-исключение; изменяет сохранённую легенду при Selection; удаляет или изменяет исходный Media Asset при снятии связи или экспорте; запрещает экспорт изображения без точек; скрывает ошибку импорта; не открывает старый проект; или заметно расходится с утверждённым экраном.

## Формат отчёта QA

Для каждого изменения QA указывает: версию приложения, номер сценария, набор данных, результат, путь к скриншотам, найденные регрессии и вердикт `принято`/`не принято`. «Тесты прошли» без списка сценариев не является отчётом.

Дополнение AT-17/18: на фиксированной бинарной/тройной диаграмме проверить снятие общего отбора пустым кликом, Shift/Ctrl/Alt + активацию точки, Ctrl+A только в текущем видимом диапазоне и Esc/Home; сверить точные ID на соседних панелях, независимый zoom, неизменность Measurement и Plot Visibility. Проверить видимый focus и подсказку жестов, включая отсутствие реакции при вводе текста.
