# ADR-0001: Contract-first workflow

- **Status:** Accepted
- **Date:** 2026-08-28

## Context

Длинные циклы «сделать красиво — переделать — влить» смешивали продуктовые, архитектурные и кодовые решения. Пользователь принимает поведение приложения, а не реализацию.

## Decision

Работа идёт в порядке: макет и состояния → пользовательское утверждение → доменный/архитектурный контракт → vertical slice → независимая QA-проверка. Неутверждённый экран не реализуется как production UI. Утверждённые изображения хранятся в `docs/design/reference` вместе со связанными сценариями.

## Consequences

Начало кодирования иногда откладывается, зато изменения ограничены наблюдаемым сценарием, а следующий агент получает короткий источник истины вместо истории чата.
