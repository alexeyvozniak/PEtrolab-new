# Аудит импорта реальных исходных таблиц — полный нормативный прогон, 2026-09-03

## Итог

Все девять предоставленных исходников теперь открываются непосредственно в
PetroLab и строят воспроизводимый план импорта. Это включает семь `.xlsx` и два
старых BIFF `.xls`; пользователю больше не нужно вручную пересохранять `.xls` в
новый формат.

Исходные книги добавлены в нормативный регрессионный корпус без изменения байтов.
`manifest.json` фиксирует SHA-256 и ожидаемую первую проекцию каждой книги, а
`tests/test_normative_raw_corpus.py` повторяет тот же scientific pipeline,
который вызывает desktop-приложение. Хеш до и после каждого прогона обязан
совпадать.

Ни одна неоднозначная единица не подставляется автоматически. Вместо повторения
сотен действий PetroLab выдаёт точные server-issued группы одинаковых
Measurement-полей. Все прочие нераспознанные поля можно проверить, при
необходимости назначить вручную, а затем одним явным действием исключить
оставшийся точный набор. Measurement-кандидаты никогда не попадают в это
массовое исключение.

## Что исправлено в scientific pipeline

| Было | Стало |
| --- | --- |
| Два `.xls` требовали ручной конвертации. | BIFF `.xls` читается нативно через отдельный read-only reader и остаётся неизменным. |
| Широкая таблица `Спектр 1…122` могла ошибочно развернуться. | Явная identity-колонка и несколько measurement-заголовков блокируют ложную транспозицию. |
| Возможен «успешный» import с `0 / 0`. | `IMPORT_PLAN_EMPTY` останавливает запись до создания Source или Import Batch. |
| Поля без единицы или роли можно было потерять. | `MAPPING_REVIEW_REQUIRED` требует явного назначения либо явного Ignore. |
| Сотни одинаковых unit-вопросов повторялись. | Единица применяется только внутри fingerprint-bound группы одинаковой структуры. |
| Сотни оставшихся неизвестных полей требовали отдельных Ignore. | Точный текущий набор можно явно исключить один раз; изменение рецепта делает scope устаревшим. |
| `n.d.` могло быть принято за заголовок `Nd`. | Маркер отсутствующего значения исключён из распознавания заголовков. |

## Что исправлено в интерфейсе импорта

- слева показывается один пункт на лист, а повторные таблицы раскрываются только
  внутри выбранного листа;
- весь лист можно включить или исключить одним действием, кроме последнего
  импортируемого листа;
- физический предпросмотр остаётся центральной рабочей областью;
- структура блока скрыта под компактным раскрытием и не заслоняет исходную
  таблицу;
- инспектор сопоставлений больше не создаёт вложенную горизонтальную прокрутку;
- по умолчанию видны только поля, требующие решения;
- групповые unit-решения и явное исключение неизвестных полей находятся над
  точечным редактором;
- кнопка «Предпросмотр результата» теперь работает: показывает Analysis,
  Measurement и физическое происхождение, поддерживает поиск по всему плану;
- нижняя панель постоянно показывает число Analysis, Measurement и блокирующих
  решений.

## Результаты по нормативному корпусу

«Минимум решений» ниже означает короткий безопасный путь: единица для каждой
строгой группы, одно явное исключение оставшихся нераспознанных полей (если они
действительно не нужны) и одно подтверждение возможных совпадений. Пользователь
всегда может сначала назначить важные неизвестные поля вручную.

единицы plan перестраивается до сохранения.

## Просмотр импортированных анализов

Экран «Анализы» приведён к утверждённой трёхпанельной механике:

- источники и листы слева;
- большая таблица в центре;
- полная карточка выбранного анализа справа;
- глобальный поиск работает по всем данным, включая скрытые колонки;
- доступны фильтры каждой колонки, сортировка и настройка видимости;
- выбранные строки закрепляются сверху и сохраняются в нижней Selection-панели;
- правая панель показывает все Measurement без прежнего скрытого ограничения в
  14 полей, включая единицу, method, measurement set, исходный заголовок и
  координату ячейки;
- страницы по 500 Analysis догружаются без молчаливого обрезания проекта.

## Автоматическая приёмка

- Python regression включает весь нормативный корпус;
- два кликовых UI-сценария: Clean Table и сложная многоблочная книга;
- UI-тест нажимает выбор файла, исключение целого листа, групповую единицу,
  подтверждение совпадений, результатный preview, сохранение, поиск, Selection и
  просмотр Measurement после 14-го поля;
- статические Tauri-контракты проверяют staging, protocol envelope, paging,
  `.xls` file picker, научный child process и Windows installer gate.

Финальный release gate выполняется на `windows-latest`: установка и запуск
нативного окна остаются отдельным обязательным подтверждением перед выдачей
пользовательской Preview-сборки.
