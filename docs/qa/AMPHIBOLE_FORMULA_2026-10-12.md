# AT-45 — кальциевый амфибол, 2026-10-12

Метод: `amphibole.oxygen23/0.1.0`, статус `draft`. Научная область остаётся
ограниченной bulk APFU на 23 кислородных эквивалента. Реализация и fingerprint
установленного метода не менялись в этом срезе.

## Доказательства

Внешний эталон: [публикация, Table 2, TN8](https://pmc.ncbi.nlm.nih.gov/articles/PMC10142192/).
Исходные оксиды: SiO₂=58.8, MgO=21.5, CaO=10.4, NiO=9.1 wt.%; опубликованные
округлённые APFU: Si=8.0, Mg=4.4, Ca=1.6, Ni=1.0, допуск 0.1 APFU.
Ожидаемые значения переписаны из таблицы и не подготовлены production-расчётом.
Дополнительные Al₂O₃, Na₂O и K₂O в QA-файле заданы явными нулями.

Нативный результат: Si=8.04454, Mg=4.38496, Ca=1.52449, Ni=1.00148 APFU;
сумма оксидов 99.8 wt.%. Неизмеренное Fe отмечено предупреждением.
После полного закрытия и запуска Tauri вновь открыт тот же Run ID
`536491d2-eb15-484b-9312-445720c3f08c` с теми же значениями и Fe-допущением.
Исходные измерения не дополняются OH, Fe³⁺ или названием вида.

Проверка выполнена в отдельном проекте `org.petrolab.amphibole-qa`,
не в пользовательском проекте. `PRAGMA integrity_check` вернул `ok`;
в QA-проекте два Analysis и один сохранённый расчёт.
Хэши исходных fixtures после сценария:

- `amphibole_tn8.csv`: `ae64c8b4a2570fb29dd47993f996a79df824f1af335d7998ce68478ee3e6aa79`.
- `amphibole_unsupported_f.csv`: `827d4468d01116fdefedb9a097915063f8e95059acd520b164dcf1d67eb1822b`.

## Сервис и регрессии

Старый локальный PyInstaller executable не содержал метода амфибола.
После `python scripts/build_windows_service.py` новый executable прошёл
`python scripts/qa_amphibole_service.py --executable desktop/src-tauri/binaries/petrolab-service.exe`.
Эта команда добавлена в Windows CI сразу после сборки sidecar.

Сценарий идёт через настоящий NDJSON process и проверяет:

1. Расчёт только после явного принятия минерала.
2. Независимый опубликованный эталон APFU и неизменённую сумму wt.%.
3. Явный F=0 блокирует расчёт; смешанный scope с пригодной и непригодной строкой
   не теряет строки и не сохраняет ни одного результата.
4. Атомарное сохранение, идемпотентный повтор и историю из нового чтения SQLite.
5. Точные Measurement IDs, единицы, версию и неизменность Measurements.
6. Отказ на старом preview, `stale` после тестового изменения входа,
   неизменность исторического payload и прежних чисел.
7. Неизменность файлов-источников и SQLite integrity.

`tests/test_amphibole_acceptance.py` выполняет тот же сценарий с Python process.
Два real-service UI-теста проверяют успешный путь с Enter и повторным открытием
истории, а также отказ с F, сохранность выбора Fe, очистку preview и отсутствие
запроса `formula.save` для ошибки.

Пройдены: `python scripts/validate_contracts.py`, 215 Python-тестов,
54 UI-теста, 26 Tauri-контрактов, 4 Sites-теста, `npm run build`,
сборка PyInstaller и AT-45 на упакованном сервисе.
GitHub CI для последующего коммита фиксируется отдельно в PR #22.

## Научные границы

Полная номенклатура амфиболов, Na-амфиболы, Mg-free составы,
измеренные F/Cl/H₂O, Fe³⁺-режимы, OH/W и распределение A/B/C/T не входят
в этот установленный метод. Неподдержанный компонент остаётся в источнике;
его нельзя удалить или принять за ноль ради успешного расчёта.
Расширение требует отдельного метода/версии и независимых benchmarks.
